# T02 notes (implementation report details)

## Deviations from the brief

1. **`DirectoryMount` has its own files** (`Core/DirectoryMount.h/.cpp`); `Core/VFS.h/.cpp` holds `IFileMount` and `VFS`.
   Only the file split differs.
2. **`Hash::XXH64(data, size, seed)` has no default seed.** With one, `Hash::XXH64("text", 12345)` would resolve to the
   pointer/size overload and read 12345 bytes from a literal. The `std::string_view` and `BufferView` overloads default
   the seed to 0. `Hasher` is XXH64 streaming (not XXH3), consistent with D-013 and `Hash::XXH64`.
3. **`HashCombine` is a plain two-argument function** (`seed`, `value`); no variadic form, because nothing needs it.
4. **gbpch.h now includes `Math/Math.h`** (glm) next to the stable Core headers, as the brief asks ("std headers +
   glm"); the existing Core headers stay because engine files rely on them.
5. **`check.py` forwards `-D VAR=VALUE`** to `build.py` (needed for the CI follow-up: CI passes `-D GB_USE_PCH=OFF`).
   `.github/workflows/ci.yml`, AGENTS.md section 4 and the build-and-test skill are updated.

## Design choices that deserve a second look

- **DMath is a bit-exact port of musl libc 1.2.6** (`sin cos tan asin acos atan atan2` from FreeBSD msun/fdlibm,
  `exp log log2 pow` from ARM Optimized Routines, `fmod` integer-only). Source: `raw.githubusercontent.com/ifduyue/musl`
  and `kraj/musl` (identical, byte for byte); git.musl-libc.org is not reachable from the sandbox. Verification: the
  original C files, compiled with GCC (`-O2 -ffp-contract=off`), were linked next to the port and compared bit for bit on
  ~10 to 20 million inputs per function (random bit patterns, all magnitudes, subnormals, multiples of pi/2, specials):
  **zero mismatches** for the GCC Debug and the Clang Release builds. The checked-in table was cross-checked against musl
  the same way (all 1179 rows).
  Changes against the original: FMA, `TOINT_INTRINSICS`, long double, rounding-mode and `FORCE_EVAL` paths removed; unions
  replaced by `std::bit_cast`; `goto`s restructured; `__rem_pio2_large` specialized to double precision with the 66-entry
  2/pi table; hexadecimal float literals are written as the shortest round-tripping decimals (MSVC support for hex floats
  is not guaranteed); `libm.h`'s `scalbn` is a multiplication by an exact power of two.
- **Canonical NaN.** Every NaN result is `0x7FF8000000000000`. The original returns `x - x`, `0/0` and similar, whose sign
  differs between x86-64 and ARM64; a NaN reaching the state hash would break cross-platform determinism.
- **Float overloads compute in double and round once.** Within 1 float ulp of `std` in the tests.
- **Accuracy tests use 2 ulp against `std`**: both sides are below 1 ulp (measured 1 against glibc), the bound leaves room
  for other platforms' libms.
- **License bookkeeping.** The musl notice (MIT) and the per-file Sun/ARM notices are in the headers of the ported files;
  `ThirdParty/README.md` lists them in a new "Source derived from other projects" section. No `DECISIONS.md` entry was
  added (this is a port, not a dependency); an entry could be added if you want one.
- **Reference table regeneration.** `GambitTests/src/Math/DMathReference.inl` is generated by the test "Math: DMath matches
  the reference table bit for bit" when `GB_UPDATE_GOLDEN=1` is set (it writes into the source tree through
  `GB_TEST_SOURCE_DIR` and then deliberately fails so that the variable is never left on unnoticed). Inputs: fixed anchors
  plus a splitmix64 sampler, 50 per function; the float table uses the same inputs where they are finite as floats.
- **VFS semantics.**
  - Not-found falls through to the next mount; any other error (I/O, corrupt pack entry) stops the lookup. Mounts signal
    "not there" with `FileError::NotFound` in `Error::Code` (`Core/FileSystem.h`).
  - `Write` goes to the newest writable mount whose mount point contains the path and where the path is not the mount root;
    `Remove` acts on the newest mount that has the path and fails with `ReadOnly` when that mount is read-only.
  - `List` merges over all mounts (newest wins), includes the virtual directories leading to mount points and returns
    full virtual paths sorted bytewise. `IFileMount::List` returns paths relative to the mount root.
  - Reads take a snapshot of the (immutable, copy-on-write) mount list under a short mutex and then work lock-free, so
    slow I/O never blocks `Mount`/`Unmount`. `std::atomic<std::shared_ptr>` was avoided on purpose (AppleClang 15).
  - Virtual paths are normalized with `FileSystem::NormalizePath`: backslashes become slashes on every platform, and
    segments containing control characters or `:` are rejected (alternate data streams, drive tricks).
  - `DirectoryMount` is confined by resolving symbolic links (`weakly_canonical`) and comparing path components with the
    canonical root, so links pointing outside the root are rejected (a deliberate choice: shared asset folders must be
    mounted explicitly instead of symlinked). `Remove` deletes a final symbolic link, not its target.
  - **Case sensitivity is not enforced by `DirectoryMount`** on case-insensitive file systems (Windows, default macOS); the
    VFS layer itself and packs are case-sensitive. Enforcing it would need a directory scan per path segment and could not be
    tested on the Linux sandbox. Content that only works with wrong case will fail when exported to a pack.
- **FileSystem.** `ReadText` drops a UTF-8 BOM but keeps line endings. `WriteBinary` writes `<name>.<random>.tmp` next to the
  target and renames it over the target (atomic on POSIX and Windows); data is not fsync'ed. `ListDirectory` sorts by path
  so that listings are identical on every file system. `ToUtf8`/`FromUtf8` keep virtual paths UTF-8 on Windows.
- **UUID.** `Parse` requires the `0x` prefix and 1 to 16 hex digits; the null UUID parses (serialized null references).
  `Generate` uses one `std::mt19937_64` per thread, seeded from 256 bits of `std::random_device` (clock fallback with a
  warning when the OS refuses entropy). The constructor from `uint64_t` is explicit.
- **Random.** PCG32 as in `pcg32_srandom_r`/`pcg32_random_r`; bounded integers use the reference rejection method
  (`pcg32_boundedrand_r`), so `NextBounded(6)` equals the pcg-c library's output for the same seed. `NextU64` and
  `NextDouble01` use two draws (high word first; the expression is sequenced explicitly because the order of evaluation of
  operands is unspecified). `NextGaussian` is Box-Muller using only the cosine branch, so the generator state stays the only
  state. `SetState` returns false for an even increment. `Shuffle` takes `std::span<T>`; inputs larger than 2^32 items use a
  64-bit sampler. `RangeInt(min > max)` returns `min` (assert-free, no draw).
- **glm** is configured through PUBLIC compile definitions of the `Gambit` target (and the test links `glm::glm` itself as
  before); `GLM_FORCE_INTRINSICS` stays off and the test file fails to compile if a SIMD macro appears.
- **PCH.** `GB_USE_PCH` only controls `target_precompile_headers`; every engine `.cpp` includes `gbpch.h` explicitly, so
  both modes compile the same code.

## Tests

`Core:` UUID 9, Buffer/BufferView 8, Hash 8, FileSystem 15, VFS/DirectoryMount 21 (including a concurrency test with
mounts changing under 4 reader threads), Timer/TimeStep 3. `Math:` Math.h 8, DMath 12 (accuracy, special values, canonical
NaN, identities, float overloads, reference tables), DMath rotation helpers 8, Random 16. Total new: 108 test cases; at the
end of T02 the suite was 169 test cases and 5 CTest smoke tests.

## Verified

- GCC 13.3 and Clang 18.1: Debug, Release and Dist build warning-free and pass `scripts/check.py`; GCC with
  `-D GB_USE_PCH=OFF` as well.
- AddressSanitizer + UBSan (all engine tests) and ThreadSanitizer (`Core:` and `Math:` tests) are clean.
- No fused multiply-add instruction in the Clang Release engine library (`objdump`).

## Not verified (no access here)

- MSVC and AppleClang. Most likely to need a touch-up there: `std::format("{:a}")` of floating-point values in test failure
  messages, `windows.h`/`_NSGetExecutablePath` code in `GetExecutableDirectory`, symbolic-link tests (skipped when the
  platform refuses to create links), `/W4` on the ported code (it uses unsigned wrap-around deliberately).
