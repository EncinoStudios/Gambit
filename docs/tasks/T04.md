# T04 — Reflection, World/ECS, systems, state hash

Read first: `AGENTS.md`, D-011, D-013, D-020..D-024 in `docs/DECISIONS.md`. Builds on T01–T03.
This is the heart of the engine; design for every later module (physics, scripting, editor, CLI) to plug in
through reflection without per-component code.

## Deliverables (with doctest tests)
1. **TypeRegistry** (`Reflection/`):
   - `FieldType`: Bool, Int32, UInt32, Int64, UInt64, Float, Double, Vec2, Vec3, Vec4, Quat, Color3, Color4,
     String, Entity (UUID reference to another entity), AssetHandle (+ required asset type), Enum (+ name/value
     list), plus `Array` of any scalar/vector/String/Entity/AssetHandle element type (`std::vector`).
   - `FieldInfo`: name, type, attributes (`Range{min,max}`, `Tooltip`, `Hidden`, `ReadOnly`, `NotSerialized`,
     `NotHashed`, `AssetType`, `EnumInfo`, `Category`), type-erased get/set into a `FieldValue`
     (`std::variant` covering all types) and raw pointer access.
   - `ComponentInfo`: name (stable, used in files/Lua/CLI), id, fields, flags (`Serializable`,
     `EditorVisible`, `Removable`, `Internal`), and type-erased ops against a `World`+entity: `Has`, `Add`
     (default-constructed), `Remove`, `GetRaw`, `CopyTo(otherWorld, otherEntity)`, `ForEach`. Backed by templates
     for C++ components and by `DynamicComponent` storages for script components (D-023): schema of
     `FieldInfo` + defaults, values stored in a compact per-instance buffer/variant array, EnTT named storage
     keyed by the component id. Registering/unregistering dynamic schemas at runtime must be safe.
   - Registration API: `TypeRegistry::RegisterComponent<T>("Transform").Field("Translation",
     &TransformComponent::Translation, attrs...)...`; enums via `RegisterEnum<E>`. Lookup by name/id/type.
2. **World** (`ECS/World.h/.cpp`) wrapping `entt::registry`, and **Entity** handle (`ECS/Entity.h`, Hazel
   style: `AddComponent<T>`, `GetComponent<T>`, `HasComponent<T>`, `RemoveComponent<T>`, `GetUUID`, `GetName`,
   validity checks with asserts).
   - Entity lifecycle: `CreateEntity(name)`, `CreateEntityWithUUID(uuid, name)`, `DestroyEntity` (destroys
     children recursively), UUID→entity map, `FindEntityByName`, `TryGetEntity(UUID)`.
   - Deterministic runtime spawning: `World::GenerateUUID()` draws from the world `Random` (D-011).
   - Hierarchy via `RelationshipComponent` (parent UUID + ordered child UUID vector): `SetParent(child,
     parent, keepWorldTransform)`, `GetChildren`, `GetRoots` (stable order), `IsAncestorOf`; cycles rejected.
   - `CommandBuffer` (deferred create/destroy/add/remove/set-field) flushed by the scheduler between phases.
   - `World::Copy(const World&)` (deep copy incl. dynamic components, RNG, tick) — used for play mode.
   - Per-tick typed event queues: `World::Events<T>()` with `Emit/View/Clear` (cleared at tick start).
   - World resources: `Random`, tick index, `SimulationTime`, seed.
3. **Core components** (`ECS/Components/`): `IDComponent`, `TagComponent`, `TransformComponent` (Translation,
   Rotation quat, Scale; helpers only), `RelationshipComponent`, `WorldTransformComponent` (derived, not
   serialized/hashed), `ActiveComponent`/disabled flag approach (pick one: entities with
   `DisabledComponent` are skipped by systems; inherited by children). All registered in the TypeRegistry
   (Entity-type fields for parent/children).
4. **Systems** (`ECS/System.h`, `ECS/SystemScheduler.h`): `ISystem` (`GetName`, `GetPhase`, `GetOrder`,
   `RunsInEditMode`, `OnCreate(World&)`, `OnUpdate(World&, TimeStep)`, `OnDestroy(World&)`), phases from D-024,
   deterministic ordering (phase, order, name), enable/disable per system, CommandBuffer flush after each phase,
   per-system timing stats (wall clock; stats only, never fed back). `TransformSystem` (Transform phase)
   computes `WorldTransformComponent` hierarchically (parents before children, stable order).
   `World::Tick(TimeStep, mode)` runs one fixed simulation step.
5. **State hash** (D-013): `World::ComputeStateHash()` — deterministic order (sort entities by UUID), hash
   every hashed reflected field of every component (component name + field values; floats by bit pattern),
   dynamic components included, RNG state, tick.
6. **Tests**: registration/lookup, field get/set for every `FieldType`, dynamic component register/add/
   get/set/remove/copy, entity lifecycle + UUID map consistency, hierarchy ops + cycle rejection, transform
   propagation, CommandBuffer semantics, scheduler ordering, World::Copy equality (state hash equal),
   state-hash sensitivity (changing any field changes hash) and stability (same ops → same hash; different
   creation order of unrelated entities with same UUIDs → same hash), determinism: two worlds running a
   test system that spawns/destroys entities with world RNG for 1000 ticks produce identical hashes every tick.

## Follow-ups from T02/T03 review (do these first, with regression tests; see docs/tasks/T02-T03-review.md)
- VFS: a write whose path equals/lies under a mount point must go to the highest-priority writable mount that
  contains it (currently lands in an older mount).
- `NormalizePath`/VFS: reject Windows reserved device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1-9`, `LPT1-9`, with
  or without extension, case-insensitive) and trailing dots/spaces in components, on every platform, so projects
  stay portable.
- FileSystem/VFS: distinguish permission-denied (and other IO errors) from NotFound in error codes.
- InputLog/InputFrame load: reject out-of-range gamepad axis values and any other field outside its valid range.
