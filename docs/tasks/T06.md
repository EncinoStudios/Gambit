# T06 — Command registry, undo/redo, `gambit` CLI, comments

Read first: `AGENTS.md`, D-022, D-027, D-050..D-052 in `docs/DECISIONS.md`. Builds on T01–T05.
This is the API that editors, the CLI, the MCP server (T22) and agents all use. Design it so a coding agent
can build a whole game through it.

## Deliverables (with doctest tests)
1. **Command framework** (`Automation/`):
   - `CommandInfo`: dotted name (`entity.create`), summary, argument schema (JSON Schema subset: type, required,
     enum, default, description — enough to export as MCP tool schemas later), result description, flags
     (`Mutating`, `Undoable`, `RequiresScene`, `EditorOnly`).
   - `CommandRegistry`: register, list (filter by prefix), `Execute(EditorContext&, name, json args)` →
     `CommandResult` (ok + JSON payload | error message + code). Argument validation against the schema before
     the handler runs (clear messages naming the bad arg). No exceptions escape.
   - `UndoStack` of undoable operations: each mutating command produces an `IUndoableOperation`
     (`Undo/Redo/GetDescription`); generic implementations based on reflected snapshots (entity subtree
     snapshot JSON before/after, component field before/after) so new commands rarely need custom undo code.
     Merge consecutive same-field edits (for gizmo drags), transaction grouping (`BeginGroup/EndGroup`), dirty
     tracking per scene.
   - `EditorContext`: active `Project`, open scenes (path ↔ World), active scene, selection (ordered UUID list),
     undo stack, log ring-buffer access, play-state hooks (filled in by the editor later).
2. **Commands** (each with tests): `project.new/info`, `scene.new/open/save/close/list/set-active`,
   `entity.create` (name, parent, components with initial field values), `entity.destroy/rename/reparent/
   duplicate/list` (tree or flat, filter by component/name)/`get` (all components as JSON)/`find`,
   `component.add/remove/get/set` (set accepts a partial field object; validates via reflection),
   `component.types` (all component schemas from the TypeRegistry, including dynamic), `selection.get/set`,
   `undo`, `redo`, `asset.list/info/import` (import = copy file into project + meta), `data.tables/get/set/
   add-row/remove-row`, `bulk.get` (component X across all entities in a scene → `{columns, rows}`) and
   `bulk.set` (apply a table of edits; one undo group), `bulk.export-csv/import-csv`, `sim.run` (copy active
   scene, tick N fixed steps headless, return state hash + optional component dump), `prefab.create/
   instantiate`, `log.read`.
3. **Comments** (D-052) in `Automation/Comments.h` (or `Project/Comments.h`): `CommentThread` (id, target
   {kind, scene, entity UUID, component, asset path/handle, file + line, feature tag, position}, author, status
   open/resolved, created/updated timestamps (UTC ISO-8601 — wall clock is fine here, not simulation),
   messages[] {author, text, timestamp}), stored one JSON file per thread in `<Project>/Comments/<id>.json`.
   `CommentStore` load/save/query (by target, status, author). Commands `comment.add/reply/resolve/reopen/
   list/get/delete`. Comments never enter exports.
4. **`gambit` CLI** (`GambitCLI/`): `gambit <command> [--project <dir|.gproject>] [--scene <path>]
   [--args '<json>' | --<arg> <value>...] [--json]` executes one registry command (dotted name or
   `gambit entity create ...` spaced form), saves dirty scenes unless `--dry-run`, prints a human summary or the
   JSON result with `--json`; exit codes: 0 ok, 1 command error, 2 usage error. `gambit help [command]` prints
   generated docs from schemas. `gambit batch --project P <file.jsonl>` runs many commands in one
   process (one per line `{"command":..., "args":{...}}`), stops on first error unless `--keep-going`.
   `gambit commands --json` dumps all schemas (used for docs + MCP).
5. **Docs/skills**: `docs/guides/Automation.md` (command model, CLI usage, examples building a tiny scene) and
   `.claude/skills/gambit-cli/SKILL.md` (how agents drive projects with the CLI, leave comments).
   `.claude/skills/add-command/SKILL.md` (recipe to add a command + test).
6. **Tests**: registry validation errors, each command happy path + main error paths, undo/redo for every
   mutating command (state hash returns to the previous value), undo grouping/merging, bulk get/set/CSV
   round-trip, comment store CRUD + persistence, CLI end-to-end via process spawn of the built `gambit`
   binary on a temp project (create project → scene → entities → save → reload → verify).
