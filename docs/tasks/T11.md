# T11 — Lua scripting runtime & core API

Read first: `AGENTS.md`, D-011, D-020..D-024, D-041 in `docs/DECISIONS.md`. Builds on T01–T06.
Scripts are **content** that declares components, systems and tests. Gameplay state lives in components only.

## Script model (normative)
```lua
-- Projects/X/Scripts/Spin.lua
Component("Spin", { Speed = 1.0, Axis = Vec3(0, 1, 0), Count = Int(0), Target = EntityRef(), Mode = Enum({"Local", "World"}, "Local") })

System("SpinSystem", {
    Phase = "Update", Order = 0,
    OnCreate = function(world) end,           -- optional
    OnUpdate = function(world, dt)
        for entity, transform, spin in world:Query("Transform", "Spin") do
            transform.Rotation = transform.Rotation * Quat.AngleAxis(spin.Speed * dt, spin.Axis)
        end
    end,
})
```
- Field types inferred from defaults (number→Float, boolean→Bool, string→String, Vec2/3/4/Quat/Color→same) or
  explicit constructors (`Int`, `UInt`, `Float`, `Double`, `Bool`, `String`, `Vec2..4`, `Quat`, `Color3/4`,
  `EntityRef`, `Asset("Texture")`, `Enum(names, default)`, `Array(type, default)`). Declared components become
  dynamic components (D-023) — serializable, inspectable, hashable.
- Component access returns live **reference proxies** resolved through the TypeRegistry (C++ and Lua components
  alike): `entity:Get("Transform").Translation = Vec3(1,2,3)`; vector-typed fields return bound proxies so
  `transform.Translation.x = 5` writes through; arithmetic yields plain values. Proxies re-validate the
  entity/component on every access and raise a clear Lua error when stale.
- Structural changes from Lua (spawn, destroy, add/remove component) are immediate; `world:Query` iterates a
  snapshot of matching entities and skips ones destroyed mid-iteration — deterministic and safe.
- After all scripts load, writes to globals raise an error (enforces "state lives in components").
- One Lua state per simulation `World`; recreated for every play session/test; schemas also loaded in edit mode
  (systems don't run in edit mode unless `RunInEditMode = true`).

## Deliverables (with tests)
1. **Lua build**: Lua 5.4 static lib target from `ThirdParty/lua` (exclude `lua.c`/`luac.c`, compile as C,
   `luai_makeseed` fixed via compile definition per D-041, `LUA_USE_*` platform defines), sol2 interface target
   (`SOL_ALL_SAFETIES_ON` in Debug/Release, `SOL_LUA_VERSION=504`). Bindings split across several TUs to keep
   compile times sane.
2. **`Scripting/ScriptEngine`**: owns a `sol::state` per World; sandbox (base without `dofile/loadfile`,
   `load` text-only with sandbox env; string, table, utf8, coroutine; math with `random/randomseed` → world
   `Random`, trig/exp/log/pow → `DMath`; no `io/os/debug/package`; `print` → logger); `require` resolves
   modules from `<Project>/Scripts/` and the engine Lua library (`Gambit/Lua/`) through the VFS; script
   discovery = all `Scripts/**/*.lua` in sorted path order; Lua errors carry file:line and are reported via
   logger + `Result` (a failing system is disabled for the session with an error, never crashes the engine);
   memory limit (custom allocator with cap) and an instruction-count watchdog per system update
   (configurable; reports runaway loops).
3. **`ScriptSystem`**: wraps each Lua `System` as an `ISystem` in the scheduler (phase/order/name, D-024).
4. **Core API** (each function documented in an `ApiRegistry` entry: signature, description, example):
   - Math: `Vec2/Vec3/Vec4/Quat/Color/Mat4` userdata with operators, `Dot/Cross/Length/Normalize/Lerp/Distance`,
     `Quat.AngleAxis/Euler/LookRotation/Slerp/Inverse`, `Math.Clamp/Lerp/InverseLerp/SmoothStep/MoveTowards/
     DeltaAngle`, constants `Math.Pi`. All deterministic (DMath).
   - World: `Spawn(name?, components?)`, `Destroy(e)`, `Find(name)`, `FindByUUID(str)`, `Query(...)`,
     `QueryFirst(...)`, `Count(...)`, `Instantiate(prefab, opts)`, `Emit(event, payload)` / `Events(event)`
     (per-tick script events, payload tables deep-copied to plain data), `Tick`, `Time`, `DeltaTime`,
     `LoadScene(path)` (applies at end of tick), `Random` (`Float/Range/Int/Bool/Gaussian/InsideUnitSphere`).
   - Entity: `Get/Has/Add/Remove`, `Name`, `UUID`, `IsValid`, `Parent`/`SetParent`, `Children`, `Destroy`,
     `IsEnabled/SetEnabled`, `WorldPosition/WorldRotation` (read world transform), equality.
   - Input: `Input.IsDown/WasPressed/WasReleased(action)`, `GetAxis/GetAxis2D`, raw `IsKeyDown(Key.X)`,
     `MouseDelta`, gamepad — all read from the tick's `InputFrame` (deterministic).
   - Data: `Data.Get(table, row)` (read-only row proxy), `Data.Rows(table)`, `Data.Has`.
   - Log: `Log.Info/Warn/Error` (+ `print`), `Debug.DrawLine/DrawBox/DrawSphere(color, duration)` — debug draw
     queue consumed by the renderer later (store as world-independent debug primitive list now).
   - Engine Lua library `Gambit/Lua/`: `Class`-free helpers only (`SortedPairs`, `Table.Copy`, `StateMachine`
     helper that stores state in a component field) — keep small.
5. **Binding extension point**: `ScriptEngine::RegisterBinder(name, fn)` so later modules (physics, audio,
   animation, UI, particles) add their Lua API in their own module files, each with `ApiRegistry` docs.
6. **Tests** (C++ doctest driving Lua): sandbox (forbidden libs absent, `load` binary rejected, global freeze),
   component declaration + type inference + explicit types, proxy read/write for every FieldType incl. vector
   write-through and stale-proxy errors, query snapshot semantics with spawn/destroy during iteration,
   system ordering with C++ systems, errors with file:line, watchdog + memory cap, Random determinism
   (`math.random` sequence equals world RNG), DMath-backed `math.sin` bit-equality with `DMath::Sin`, a
   determinism test: a script-driven simulation of 600 ticks with spawns/destroys/random yields identical state
   hashes across two runs, and an `ApiRegistry` completeness test (every bound function/table entry documented).

## Note from T04 review
Lua needs event access by name (`world:Events("CollisionEnter")`): register event types in the TypeRegistry
(reflected structs, see T05's `Struct` FieldType) so Lua reads them generically; Lua-emitted script events are
plain-data payloads. Consider replacing hand-written `HashEvent` with reflection-driven hashing if it simplifies.
- From T05 review: `Instantiate` is immediate. C++ systems get `CommandBuffer::Instantiate(prefab, ...)` (deferred,
  deterministic UUIDs at flush); Lua keeps immediate semantics with snapshot queries.
