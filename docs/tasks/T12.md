## Test model (normative)
```lua
Test("Spin rotates entity", {
    Scene = "Scenes/SpinTest.gscene",   -- optional; default: empty world with project scripts loaded
    Tags = { "gameplay" },             -- optional
    Timeout = 600,                      -- max ticks, optional (default 3600)
    Run = function(t)
        local e = t.World:Spawn("S", { Transform = {}, Spin = { Speed = 2.0 } })
        t:Tick(60)                                   -- advances fixed ticks
        t:Press("Jump") t:Tick(1) t:Release("Jump")  -- simulated input via actions or raw keys (t:PressKey(Key.Space))
        t:SetAxis2D("Move", Vec2(0, 1))
        t:Expect(e:Get("Spin").Speed == 2.0, "speed unchanged")
        t:ExpectEq(a, b, msg) t:ExpectNear(a, b, eps, msg)  -- numbers and vectors
        t:ExpectTrue/ExpectFalse/ExpectError(fn, pattern)
        t:WaitUntil(function() return cond end, maxTicks)    -- ticks until true or fails
        t:Log("...")
    end,
})
```
- Tests can live in any script (next to the feature they test) or `Tests/*.lua`. In `Dist` exports `Test` is a
  no-op and test-only files under `Tests/` are not packed.
- Each test runs in a fresh Lua state + fresh World (scene copy), deterministic seed (project seed, overridable
  per test with `Seed = n`). Input injection builds `InputFrame`s so the same path as real input is exercised.
- A failing expectation records file:line and continues; an error aborts that test. Timeout fails the test.

## Deliverables (with tests)
1. `Scripting/LuaTestRunner`: discovery (all tests across project scripts), filtering by name substring/tag,
   execution, results (`passed/failed/errors/skipped`, durations in wall clock, tick counts, messages with
   file:line), JUnit XML writer, human summary.
2. Commands `test.list` and `test.run` in the CommandRegistry (so MCP/editor get them) and CLI sugar:
   `gambit test --project P [--filter X] [--tag T] [--junit out.xml] [--json]`; exit code 0 all passed, 1 any
   failure. Quiet output: one line per failure + summary.
3. Replay check helper: `t:RecordReplay()` / `gambit test --verify-determinism` runs every test twice and
   compares per-tick state hashes, reporting the first divergent tick.
4. **API stubs**: `gambit api-stubs --out <dir>` writes LuaLS (`---@meta`) annotation files generated from the
   ApiRegistry + TypeRegistry (component classes with typed fields, including project-declared components when
   `--project` is given) and a `.luarc.json`; `gambit api-docs --out docs/api/Lua.md` writes markdown reference.
   Commit the generated `docs/api/Lua.md` for the engine API.
5. Create the skeleton of `Projects/FeatureTest/` (project file, `Scripts/`, `Tests/`, `Scenes/`) with tests
   covering the T11 core API (math, world, entity, input injection, data tables, events, random determinism).
   This project grows with every later task (T25 completes it). Add a CTest entry that runs
   `gambit test --project Projects/FeatureTest --verify-determinism` so `scripts/check.py` covers it.
6. Tests: runner discovery/filter, expectation failure reporting with file:line, timeout, error isolation
   between tests, JUnit XML well-formedness, determinism verification catching an injected non-determinism
   (a test-only C++ system using wall-clock), stub generation contains every API entry.
