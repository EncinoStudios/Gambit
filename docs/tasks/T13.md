# T13 — Physics (Jolt)

Read first: `AGENTS.md`, D-011, D-020, D-022, D-024, D-040, D-041 in `docs/DECISIONS.md`. Builds on T04, T05, T11, T12.

## Deliverables (with tests)
1. **Build**: Jolt static lib from `ThirdParty/JoltPhysics/Build` (or own target list) with
   `JPH_CROSS_PLATFORM_DETERMINISTIC`, `JPH_OBJECT_STREAM` off, asserts in Debug, no profiler/debug renderer in
   Dist, warnings off for Jolt. Same defines on every consumer (interface definitions).
2. **Components** (all reflected, serializable, editable): `RigidBodyComponent` (BodyType Static/Dynamic/
   Kinematic, Mass (0 = from shape density), LinearDamping, AngularDamping, GravityFactor, Friction, Restitution,
   IsSensor, AllowSleeping, MotionQuality Discrete/LinearCast, LockTranslation/Rotation axes (bool3), Layer
   (named collision layers from project settings), InitialLinearVelocity/AngularVelocity),
   `BoxColliderComponent` (HalfExtents, Offset, Rotation), `SphereColliderComponent`, `CapsuleColliderComponent`
   (Radius, HalfHeight, axis Y), `CylinderColliderComponent`, `ConvexHullColliderComponent` (Mesh asset handle or
   inline point array), `MeshColliderComponent` (static/kinematic only; mesh asset handle), compound bodies from
   child colliders without their own RigidBody, `CharacterControllerComponent` (Jolt `CharacterVirtual`: Height,
   Radius, MaxSlopeDeg, StepHeight, Mass, MaxStrength, + runtime-state fields: Velocity, IsGrounded,
   GroundNormal, GroundEntity — runtime fields NotSerialized but hashed), joints: `FixedJointComponent`,
   `HingeJointComponent`, `DistanceJointComponent` (ConnectedEntity, anchors, limits, motors where applicable,
   BreakForce/BreakTorque → joint breaks + event; needed for destruction). Collision layer matrix in project
   settings (`Physics.Layers`, `Physics.Collisions`).
   Runtime velocity state: expose `LinearVelocity/AngularVelocity` fields on RigidBody synced from Jolt each tick
   (hashed) so the state hash covers physics.
3. **PhysicsSystem** (Physics phase, D-024): creates/destroys Jolt bodies in response to component
   add/remove/changes (deterministic order: sorted by UUID when batching), pushes kinematic targets and
   Transform edits of static/kinematic bodies, steps Jolt exactly once per tick with fixed collision steps,
   writes dynamic body transforms back to `TransformComponent` (world → local, respecting parents), syncs
   velocities, runs `CharacterVirtual::ExtendedUpdate` for characters with desired velocity from the component.
   `PhysicsWorld` (core service, non-ECS) owns the `JPH::PhysicsSystem`, `TempAllocator`, `JobSystemThreadPool`
   (thread count configurable; determinism holds with any count — test it), layer interfaces.
4. **Events**: contact listener collects `CollisionEnter/Stay/Exit` and `TriggerEnter/Exit` (entity A/B UUIDs,
   contact point, normal, impulse) into world event queues (D-021/T04) in deterministic sorted order;
   `JointBroken` events.
5. **Queries**: `Raycast(origin, dir, maxDist, layerMask)` → hit (entity, point, normal, distance, fraction),
   `RaycastAll`, `ShapeCast` (sphere/box/capsule), `Overlap` (sphere/box/capsule), all with deterministic result
   ordering. Forces: `AddForce/AddImpulse/AddTorque/AddAngularImpulse/SetLinearVelocity/MoveKinematic` via a
   `PhysicsCommands` queue applied before the step (systems request, PhysicsSystem applies — no direct Jolt
   calls from gameplay systems).
6. **Lua API** (via `RegisterBinder`, ApiRegistry-documented): `Physics.Raycast/RaycastAll/ShapeCast/Overlap`,
   `Physics.AddForce/AddImpulse/AddTorque/SetVelocity/GetVelocity`, `Physics.SetGravity/GetGravity`, events via
   `world:Events("CollisionEnter")` etc., character: `Physics.MoveCharacter(entity, desiredVelocity)` / component
   fields.
7. **Tests**: body creation per collider type, gravity fall time vs analytic within tolerance, restitution
   bounce, sensor triggers enter/exit, layer filtering, raycast/shapecast/overlap correctness + ordering,
   joints hold + break with event, character controller walks up steps/slopes and stops at steep slopes,
   compound colliders, transform write-back with parented entities, component edits at runtime rebuild bodies,
   **determinism**: 1000-tick stacking/collapse scene with impulses → identical per-tick state hashes across two
   runs and across job-thread counts 1 vs 3; World::Copy mid-simulation then continue → identical hashes
   (rollback). Lua tests in `Projects/FeatureTest/Tests/Physics.lua` covering the Lua API.
