# T22 — Agent control: MCP server, editor JSON-RPC, screenshots, full command coverage

Read first: `AGENTS.md`, D-051, D-052 in `docs/DECISIONS.md`, `docs/guides/Automation.md`. Builds on T06, T12, T20–T21.
Requirement: "Editor needs to be fully controllable by AI agents — I should be able to ask you to build me a game
like Tetris, and you should have all the tools available to do so without my intervention."

## Deliverables (with tests)
1. **Command coverage audit**: list every editor capability (menus, panels, play mode, settings, asset ops,
   render settings, physics layers, input actions, prefabs, data tables, comments, replays, export, tests)
   and make sure each has a registry command. Add missing ones, e.g. `script.create/read/write/list` (Lua files
   with syntax check via `luaL_loadbuffer`), `input.actions.get/set`, `project.settings.get/set`,
   `render.screenshot` (headless render of a scene/camera or the editor viewport to PNG; returns path; supports
   `--ticks N` to simulate first and `--camera <entity>`/explicit transform), `sim.run` with input script
   (actions per tick), `scene.validate` (missing assets, broken refs, script errors), `docs.search` (search
   guides/API docs for agents), `material.create/set`, `particles.*`, `ui.*` as needed.
   Write `docs/guides/AgentCapabilities.md` mapping capability → command.
2. **MCP server** (`gambit mcp --project P [--editor <host:port>]`): Model Context Protocol over stdio
   (JSON-RPC 2.0, protocol version per current MCP spec: `initialize`, `tools/list`, `tools/call`,
   `resources/list|read` for guides + API docs + project files, `prompts/list` optional, notifications,
   proper error codes). Tools are generated from the CommandRegistry schemas (names with `_` instead of `.`),
   results as text JSON + image content for screenshots. Headless mode operates on project files directly;
   `--editor` forwards every call to a running editor over its RPC port so the user sees changes live.
   Add `.mcp.json` example at repo root and docs on registering it with Claude Code.
3. **Editor JSON-RPC endpoint**: `GambitEditor --automation-port <port>` (localhost only, off by default, token
   auth via generated token file in the user config dir), JSON-RPC 2.0 over TCP (newline-delimited) or HTTP
   (cpp-httplib) — pick one and log; commands executed on the main thread between frames; streaming log
   notifications.
4. **Robustness**: concurrent requests serialized, long operations report progress, every error is a
   structured message an agent can act on (which arg, what's valid).
5. **Tests**: MCP handshake + tools/list schema validity (JSON Schema draft 2020-12 subset) + tools/call happy
   and error paths via a spawned `gambit mcp` process speaking stdio; RPC end-to-end against a headless editor;
   screenshot command produces a non-empty PNG matching a golden (gpu); an end-to-end "agent script" test that
   builds a small scene with a script and a test purely through MCP calls and runs `test.run` successfully.
6. **Skill**: `.claude/skills/build-game-with-gambit/SKILL.md` — how an agent builds a game end-to-end
   (create project, scenes, scripts, components, assets, UI, tests, screenshots to self-check, comments to leave
   questions, export).
