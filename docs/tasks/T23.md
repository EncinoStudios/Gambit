# T23 — Export: content packs and the shipping runtime

Read first: `AGENTS.md`, D-001, D-014, D-070 in `docs/DECISIONS.md`. Builds on T05, T06, T12 (and all asset types).
Requirement: "Ability to export game — executable that runs game without editing ability that we can distribute."

## Deliverables (with tests)
1. **Cooking**: `AssetCooker` converts source assets to runtime-ready forms where useful (textures: decoded +
   mips + optional BC7 later (log as future); meshes: binary `MeshSource` blob; environments: keep `.hdr`;
   scripts: Lua source text, `Tests/` and `Test(...)` blocks stripped/no-op'd; scenes/prefabs/materials: minified
   JSON) with a dependency walk from the start scene + project-declared always-include folders, so unused assets
   are excluded (report them). Deterministic output (same input → byte-identical pack).
2. **`.gpak` format** (`Content/ContentPack.h`): header (magic, version), manifest (JSON or binary: entries with
   virtual path, asset handle, type, offset, compressed/uncompressed size, BLAKE2b-256 hash), LZ4-compressed
   blocks (per-entry or chunked for large files with random access), Ed25519 signature over the manifest
   (Monocypher; key pair from `gambit keygen`, private key never stored in the project — path via env var/arg;
   unsigned dev packs allowed with a warning). Optional XChaCha20-Poly1305 encryption of entries (key embedded in
   the runtime build — document honestly that this is obfuscation, not DRM). Reader verifies everything and
   rejects tampering with clear errors.
3. **`PackMount`** VFS mount (T02 interface) with random-access reads and an LRU of decompressed blocks.
4. **Runtime player** (`GambitRuntime`, built in `Dist`): reads `game.json` beside the executable (title,
   window settings, pack path(s) or remote config, public key, start scene), mounts content, runs the start
   scene with the full engine (no editor/ImGui/automation/test runner), handles window resize/fullscreen
   toggle, clean exit, crash-safe logging to a user log dir. Command-line `--replay <file.ginput>` for replays.
5. **`gambit export`**: `--project P --out DIR [--config Dist] [--name GameName] [--sign-key K] [--encrypt]
   [--remote URL]` → DIR contains `<GameName>(.exe)` (copy of the Dist runtime, located via a `--runtime` arg or
   the CLI's own install dir), `game.json`, `<GameName>.gpak`, licenses file. Export also available as command
   `project.export`. Host platform only (document cross-platform via CI builds per platform).
6. **Tests**: pack write/read round-trip, hash/signature tampering detection, encryption round-trip, PackMount
   reads incl. large chunked files, deterministic pack bytes, cooker dependency walk (unused asset excluded),
   Lua tests stripped, end-to-end: export FeatureTest (or a small fixture project) and run the exported runtime
   headless for N frames with a determinism hash check against the editor/CLI `sim.run` hash.
