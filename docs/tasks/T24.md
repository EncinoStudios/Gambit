# T24 — Remote content, live updates, `gambit serve`

Read first: `AGENTS.md`, D-014, D-070, D-071 in `docs/DECISIONS.md`, `docs/guides/Export.md`. Builds on T23.
Requirement: optional export flag so game content is hosted on a server and the executable holds only core
systems — for live-service content updates without client updates, and so the full game is never local.

## Deliverables (with tests)
1. **Server** (`gambit serve --pack <file.gpak|dir> --port N [--bind addr] [--tls-cert/--tls-key when built with
   OpenSSL]`): HTTP endpoints `GET /v1/manifest` (signed manifest + version), `GET /v1/blocks/<hash>` (content
   blocks addressed by hash, cache headers), `GET /v1/health`; hot-swap to a newer pack version without restart
   (`--watch`); range requests; bounded concurrency; access log. Production note in docs: put a CDN/reverse proxy
   in front; this server is a reference implementation.
2. **`RemoteMount`** (VFS): fetches/validates the signed manifest (publisher public key from `game.json`),
   fetches blocks on demand with retry/backoff and timeouts, verifies BLAKE2b per block, keeps content in memory
   (bounded LRU; never written to disk by default); optional encrypted on-disk cache (`--cache` export option,
   XChaCha20 with a per-install key) for bandwidth; prefetch list from the manifest (start-scene dependencies)
   with a loading screen/progress API; offline behaviour: clear error UI, retry.
3. **Live updates**: runtime polls manifest version (interval from `game.json`, or on scene transition);
   when a new version is available it is applied at the next safe point (scene load) — never mid-simulation
   (determinism); content version recorded in InputLogs so replays fetch the matching version.
4. **Export flag**: `gambit export --remote <url>` produces the runtime + `game.json` (server URL, public key,
   update policy) and no pack; `--publish <dir>` writes the server-side pack + manifest.
5. **HTTP client**: cpp-httplib; HTTPS when OpenSSL is found at configure time (`GB_WITH_OPENSSL`); HTTP allowed
   only with signed manifests (integrity) and a warning in release builds.
6. **Tests**: spin up `gambit serve` (in-process or child) on localhost: manifest fetch + signature check,
   tampered block/manifest rejection, missing block retry/timeout, LRU eviction + refetch, live update applied at
   scene load, end-to-end remote-export of a fixture project running headless N frames with the same state hash
   as the local pack build.
